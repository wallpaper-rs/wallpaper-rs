# Luces, 3D, cámara y profundidad

Esta página reúne todo lo que da relieve a una escena: luces que iluminan imágenes planas,
modelos 3D, sombras, una cámara que se mueve entre ellos y formas de dar profundidad a una imagen
plana. Los ejemplos salen de [`ejemplos/luces`](ejemplos/luces/scene.json),
[`ejemplos/modelo-3d`](ejemplos/modelo-3d/scene.json) y
[`ejemplos/profundidad`](ejemplos/profundidad/scene.json), y pasan `wprs-ctl scene validate`.

Las capas y los campos comunes están en [capas.md](capas.md). Las mallas con huesos (imágenes
dobladas por un esqueleto) están en [mallas.md](mallas.md).

## Luces sobre capas planas

Una capa `light` ilumina las capas que tienen un bloque `lighting`. Ella no dibuja nada. Una
escena tiene hasta 12 luces; en teléfonos y equipos antiguos solo iluminan las 8 primeras, en el
orden de las capas, y las demás se nombran en las notas de lo que se dejó fuera.

```json
    { "id": "farol", "type": "light", "light": "point", "color": "#ffd9a0", "intensity": 1.6, "radius": 700, "z": 160,
      "transform": { "position": { "timeline": "paseo",
        "keys": [[0, [400, 400]], [8, [1500, 700], "in_out_sine"], [16, [400, 400], "in_out_sine"]] } } }
```

La capa `light` lleva solo `id`, `type`, `transform` (su posición, su giro para la dirección de
un foco, un tubo o una luz direccional, y `tilt`), `anchor`, `visible`, `parent`, `inherit` y:

| Campo | Por defecto | Rango | Qué hace |
|-------|-------------|-------|----------|
| `light` | `point` | `point`, `spot`, `tube`, `directional` | El tipo: puntual, foco, tubo o direccional. |
| `color` | blanco | | El color. |
| `intensity` | 1 | 0 a 100 | La fuerza. |
| `radius` | 512 | 1 a 100000 px | Hasta dónde llega. |
| `z` | 100 | -100000 a 100000 px | La altura sobre el lienzo. |
| `cone` | `[30, 60]` | 0 a 180 grados | Solo focos: `[interior, exterior]`; lleno en el medio, oscuro más allá del ángulo exterior. |
| `length` | 256 | 1 a 100000 px | Solo tubos. |
| `volumetric` | | ver abajo | Luz que brilla en el aire. Puntuales y focos. |
| `texture` | | | Solo focos: una imagen, un vídeo o `{ "layer": id }` que la luz proyecta. |
| `shadows` | `false` | | Proyecta sombras de modelos. Ver "Sombras". |
| `shadow_resolution` | según el tipo | 256 a 4096 px | Tamaño del mapa de sombras. |
| `shadow_bias` | 0,2 | 0 a 1 | Qué tanto se levantan las superficies de su propia sombra. |
| `position3d` | | `[x, y, z]` | Dónde está entre los modelos. Ver "Luces entre modelos". |
| `aim3d` | | `[x, y, z]` | A dónde apunta un foco o una luz direccional entre los modelos. |

`color`, `intensity`, `radius`, `z`, `position3d` y `aim3d` pueden seguir valores o claves. Una luz
sigue a sus padres, grupos y huesos (`attach`) como las demás capas. El `radius` y el largo de una luz se miden siempre en píxeles del plano de foco de la cámara, también con `position3d`.

Un foco o una luz direccional sin giro apunta hacia abajo del lienzo y gira en el sentido del
reloj con `rotation`; el primer número de `transform.tilt` (de -89 a 89) la inclina hacia dentro
del lienzo, de modo que `[90, 0]` apuntaría de frente. Un tubo se tiende a lo largo del eje x de su
capa, con `length` de largo, y ilumina como una fila de luces puntuales. La luz de una puntual, un
foco o un tubo se apaga como (1 − d²/r²)², con d la distancia en tres dimensiones (la altura `z`
incluida), y termina en el radio; una direccional llega a todas partes con la misma fuerza.

### Qué capas reciben luz

Una capa de imagen, vídeo, texto, malla, modelo o partículas recibe luz si tiene `lighting`:

```json
    { "id": "pared", "type": "image", "image": "piedra", "size": [1920, 1080],
      "lighting": { "normal": "relieve", "roughness": 0.4, "strength": 1 } }
```

| Campo | Por defecto | Rango | Qué hace |
|-------|-------------|-------|----------|
| `normal` | | | Un mapa de normales (un recurso `linear`): rojo a la derecha, verde arriba y azul hacia quien mira, de 0 a 1 para -1 a 1. |
| `roughness` | 0,5 | 0 a 1 | La aspereza: brillo agudo en lo liso, extendido en lo áspero. |
| `roughness_map` | | | Una imagen `linear` de grises que multiplica la aspereza. |
| `reflection` | 0 | 0 a 1 | Cuánto refleja de `env`, o de lo que hay debajo si no hay `env`. |
| `env` | | | Una imagen que se lee como una esfera, con la normal. |
| `emissive` | 0 | 0 a 16 | Luz propia, que se ve incluso a oscuras. |
| `emissive_map` | | | Una imagen `linear` de grises que multiplica la luz propia. |
| `strength` | 1 | 0 a 1 | Cuánto del color iluminado reemplaza al normal. |

Los números pueden seguir valores. Cada píxel suma, por cada luz, el color de la luz por su
intensidad, su atenuación, su cono y el coseno entre la normal del píxel y la dirección de la luz,
más un brillo especular. La luz de alrededor llega encima: el color de `canvas.ambient` sobre las
superficies que miran hacia abajo y el de `canvas.sky` (el ambiental si falta) sobre las que miran
hacia arriba, y negro si no pones ninguno. Una capa sin mapa de normales mira de frente y toma la
mezcla de los dos.

```json
  "canvas": { "size": [1920, 1080], "background": "#000000", "ambient": "#10131f", "sky": "#202a44" }
```

Mientras las luces no se mueven, las capas iluminadas se dibujan una vez y se guardan; cuando
una se mueve, solo se vuelve a dibujar la caja que cubre su radio. En el nivel de calidad más bajo
la iluminación se calcula una vez, al empezar, y las luces que se mueven se quedan donde estaban.
Una capa inclinada (`tilt`) o levantada (`z`) se ilumina en su propio plano. La profundidad de ese plano no cuenta el estrechamiento de la perspectiva ni el centro de la cámara: la luz supone el centro del lienzo para el ojo, así que en una inclinación fuerte puede caer algo desviada.

Un mapa de normales puede hacerse con `wprs-ctl scene normals` (a partir de los bordes de una
imagen) y los mapas de aspereza y de luz propia se pintan con `scene paint-map`.

### Luz en el aire

Una luz puntual o un foco con `volumetric` brilla en el aire dentro de su radio:

```json
    { "id": "foco", "type": "light", "light": "spot", "color": "#8fb4ff", "intensity": 1.2, "radius": 900,
      "cone": [20, 45], "z": 300, "transform": { "position": [1500, 150], "rotation": 20 },
      "volumetric": { "density": 0.25, "samples": 16, "shafts": 0.3 } }
```

| Campo | Por defecto | Rango | Qué hace |
|-------|-------------|-------|----------|
| `density` | 0,2 | 0 a 1 | Cuánto del camino recorre y con qué fuerza brilla el aire. |
| `samples` | 16 | 4 a 64 | Cuántos puntos toma por píxel. |
| `shafts` | 0 | 0 a 1 | Con 1, las partes oscuras de las capas de debajo frenan el brillo y proyectan rayos; con 0, el brillo no depende de ellas. |

El brillo se añade donde está la capa de la luz entre las demás: las capas de abajo se ven a su
través y las de arriba lo cubren. Se calcula a la mitad del tamaño de la pantalla (`q3`, `q2`) o a
un cuarto (`q1`, y en equipos de las dos clases más bajas), con la mitad de los puntos en `q1`, y
no se calcula en `q0`. Estos rayos no comparten los pasos del efecto `god_rays`, y la curva de rayos del editor es una cota calculada sobre fondo oscuro, no sobre lo que hay debajo. Dentro de un grupo inclinado el aire se dibuja plano, sin la perspectiva del grupo; dentro de un grupo saltado o recortado se dibuja después del grupo.

### Un foco que proyecta una imagen

Un foco con `texture` multiplica su color por la imagen, que llena el cono exterior como un
proyector. Un vídeo sigue sonando y pide fotogramas. `{ "layer": id }` proyecta esa capa tal como
se dibuja, con sus efectos, aunque esté oculta; la capa proyectada no puede recibir luz ella misma ni contener o leer una capa que la reciba. Hasta 4
focos de una escena proyectan.

## Modelos 3D

Una capa `model` dibuja un modelo glTF binario (`.glb`) con materiales de metal y aspereza. Sola,
se dibuja en su propia caja (`size`, el lienzo por defecto) con profundidad y luego se compone
como cualquier capa, con sus efectos, máscaras, mezcla y `transform`. Hay hasta 16 capas `mesh` y
`model` en una escena.

Los archivos `.glb` se hacen con herramientas de 3D comunes (FBX y OBJ se convierten a `.glb`). El
programa lee las cabeceras y la parte JSON una sola vez y rechaza modelos que carguen archivos de
fuera o que pidan extensiones que no sean `KHR_materials_emissive_strength`, `KHR_materials_unlit`,
`KHR_mesh_quantization` y `KHR_texture_transform`. Pueden tener hasta 2 000 000 de triángulos y 256
huesos por esqueleto. Los nombres de nodos (puntos de enganche), articulaciones (huesos), mallas
(partes), materiales, formas de mezcla y animaciones se leen del archivo y todo nombre que pongas
en la escena se comprueba contra ellos. Para ver qué trae un modelo:

```
wprs-ctl scene model-info modelo.glb
```

Dice los triángulos, los materiales, las texturas, los huesos, los clips y qué categorías de
equipo lo aguantan.

| Campo | Por defecto | Qué hace |
|-------|-------------|----------|
| `model` | obligatorio | El recurso `.glb`. |
| `position`, `rotation`, `scale` | | Tres números cada uno (o uno solo para los tres), en unidades del modelo y grados (se gira alrededor de x, luego de y, luego de z). Pueden seguir valores. |
| `size` | el lienzo | La caja en píxeles. |
| `env` | | Una imagen panorámica (equirrectangular) que reflejan los materiales: borrosa para la luz de alrededor y más nítida para lo brillante. |
| `materials` | | Por nombre de material del archivo, hasta 64: ver abajo. |
| `clips`, `animations`, `ik`, `physics`, `rules`, `shapes`, `expressions`, `hit`, `root_motion` | | Animación del modelo. Ver [mallas.md](mallas.md). |

```json
      { "id": "cubo", "type": "model", "model": "caja", "position": [-1.8, 0, 0],
        "rotation": { "timeline": "giro", "keys": [[0, [0, 0, 0]], [10, [0, 360, 0]]] },
        "materials": { "paint": { "color": "#ff8a3d", "params": { "metallic": 0.3, "roughness": 0.35 } } } }
```

### Materiales

Los materiales del archivo dan el color, el metal, la aspereza, la normal, la oclusión y el brillo
con sus factores. Un material de la escena multiplica su color por `color`, reemplaza el brillo
por `emissive`, elige `shader` y cambia lo demás:

| Campo | Qué hace |
|-------|----------|
| `shader` | `pbr` (por defecto), `unlit`, `fur`, `foliage`, `chroma`, o el id de un efecto propio con `stage: "material"`. |
| `color`, `emissive` | Multiplica el color; reemplaza el brillo. |
| `lit` | `false` lo dibuja sin luz. |
| `double_sided`, `cull` | Las dos caras, y qué cara se oculta: `back`, `front` o `none`. |
| `blend` | `opaque`, `mask`, `blend` o `add`. `blend` o una opacidad menor que 1 lo dibuja después de lo opaco, de lejos a cerca. |
| `depth_test`, `depth_write` | Cómo trata la profundidad. |
| `cast_shadows`, `receive_shadows` | Proyecta y recibe sombras (ambos `true` por defecto). |
| `maps` | Reemplaza mapas del archivo con imágenes de la escena: `base`, `orm`, `normal`, `occlusion`, `emissive`. Las de `orm`, `normal` y `occlusion` deben ser `linear`. |
| `params` | Parámetros del sombreador. |

Parámetros de los sombreadores:

- `pbr`: `metallic`, `roughness`, `occlusion` (0 a 1) y `normal_scale` (0 a 10).
- `fur` (pelo): `layers` (1 a 32, 12 por defecto: capas de pelo, que bajan en los niveles de
  calidad bajos), `length` (0 a 100, 10 por defecto, en centésimas del radio del modelo), `density`
  (0 a 1, 0,5 por defecto), y `comb_x`, `comb_y`, `comb_z` (-1 a 1) para peinarlo; `maps.comb`
  es una imagen `linear` que peina cada sitio por su cuenta.
- `foliage` (follaje que se mece con `canvas.wind`): `strength` (0 a 10, 1) y `speed` (0 a 10, 1).
  El rojo de los colores de vértice del archivo dice cuánto se mueve cada vértice. Sin viento
  se queda quieto y no pide fotogramas.
- `chroma`: vuelve transparentes los colores cercanos a `key` (verde por defecto), con
  `threshold` (0,4) y `softness` (0,1), de 0 a 1.
- Un efecto propio con `stage: "material"` (ver [efectos.md](efectos.md)) define
  `fn material(s: Surface) -> Surface`, que se ejecuta para cada píxel antes de la luz.
  Se compila aparte del dibujo, con el mismo plazo de 10 segundos que los demás efectos: si no
  se puede compilar o tarda más, el modelo se ve con `pbr` y el editor lo avisa entre lo que quedó
  fuera, sin que el fondo se trabe mientras tanto.

Se cambia un material por nombre desde la terminal con `wprs-ctl scene material`.

### Grupos 3D

Un grupo con `space: "3d"` dibuja todos sus modelos de una sola vez con una profundidad
compartida, en una caja del tamaño del lienzo, y se compone como una sola capa en el lugar del
grupo. Un grupo 3D dentro de otro comparte su profundidad si es "simple" (sin efectos, máscara,
mezcla, opacidad, `color`, `brightness`, `clip`, `tilt`, `z` ni `depth_test`).

Las capas planas dentro de un grupo 3D se dibujan delante de los modelos, en su orden, salvo que
pongan `depth_test`: entonces están en un plano a `transform.z` píxeles de donde mira la cámara y
los modelos que están delante las tapan. Hasta 4 planos distintos; más capas comparten el más cercano.
Las capas de partículas cuentan como planas; con `perspective` cada partícula se esconde píxel a
píxel tras los modelos, también si están iluminadas, refractan, tienen shader propio, estelas o
cuerdas (cada punto a la profundidad de su partícula), y los sistemas hijos y nietos igual. Las que
refractan ocultan su desvío tras los modelos más cercanos, pero junto al borde de uno pueden arrastrar
algunos de sus píxeles. En la calidad más baja toda la capa va en su plano.

Un modelo dentro de un grupo 3D con `opacity` menor que 1 se dibuja transparente, mezclado en luz
lineal después de los opacos, de lejos a cerca. Por eso no se desvanece igual que un modelo suelto, y no proyecta sombra.

```json
    { "id": "escenario", "type": "group", "space": "3d", "layers": [
      { "id": "suelo", "type": "model", "model": "caja", "position": [0, -1.2, 0], "scale": [6, 0.2, 6],
        "materials": { "paint": { "color": "#46506b", "params": { "roughness": 0.8 } } } },
      { "id": "cubo", "type": "model", "model": "caja", "position": [-1.8, 0, 0],
        "rotation": { "timeline": "giro", "keys": [[0, [0, 0, 0]], [10, [0, 360, 0]]] },
        "materials": { "paint": { "color": "#ff8a3d", "params": { "metallic": 0.3, "roughness": 0.35 } } } },
      { "id": "persona", "type": "model", "model": "figura", "position": [1.8, -0.2, 0], "size": [800, 800],
        "clips": [{ "id": "andar", "animation": "walk", "loop": "repeat" }],
        "animations": [{ "clip": "andar" }],
        "materials": { "body": { "color": "#9ad1ff" } } }
    ] }
```

### Cuánto cuesta

Cada modelo suma al costo de la escena una unidad por cada 200 000 triángulos en una GPU dedicada de computadora (medido en una tarjeta así) y por cada 60 000 en los teléfonos y en los equipos más modestos, que aún no se midieron; el editor y la revisión avisan con la cuenta prudente. Se cuenta otra vez lo mismo por cada mapa de sombras en el que se dibuja (las dos primeras luces con sombras; una luz puntual dibuja seis). Esa cuenta no baja con el nivel de calidad (en `t2` solo se dibuja una luz), y cada modelo paga además un costo fijo por etapa, así que una escena con muchos modelos chicos se cuenta más cara de lo que cuesta de verdad. `wprs-ctl scene bench --passes` muestra lo que tarda cada pasada de un grupo 3D: mapas de sombras, profundidad para partículas, modelos y segunda cámara. Las categorías de
equipo admiten hasta 50 000 (`t0`), 150 000 (`t1`), 500 000 (`t2`) y 2 000 000 (`t3`) triángulos,
esqueletos de hasta 256 huesos y sombras de 0, 0, 1 y 2 luces. Una categoría muestra el póster
de una escena cuyos modelos dibujan más triángulos de los que admite en el nivel más bajo; las
demás escenas pesadas corren allí con menos calidad. Las texturas de un modelo pueden ser PNG,
JPEG o WebP de hasta 4096 píxeles (2048 en teléfonos y categorías `t0` y `t1`).

```
wprs-ctl scene cost3d MI-CARPETA
wprs-ctl scene bench mi.wpak --tier t1
```

Un modelo cuyos valores no se mueven se dibuja una vez y se guarda; un grupo 3D solo se vuelve a
dibujar cuando cambia un modelo, la cámara, una luz, la luz de alrededor o el tamaño, así que una
escena quieta no pide fotogramas.

## Luces entre modelos

Sin `position3d`, cada luz está en el plano que pasa por el punto al que mira la cámara, debajo
del punto de la caja donde se dibuja, acercada a quien mira por su `z`. Con `position3d` la luz
está en ese punto entre los modelos, pase lo que pase con la cámara: puede quedar detrás o al
lado de un modelo. Con `aim3d`, un foco o una luz direccional brilla desde ahí hacia ese punto.

```json
    { "id": "sol", "type": "light", "light": "directional", "color": "#fff1d6", "intensity": 1.4,
      "shadows": true, "shadow_resolution": 1024, "shadow_bias": 0.2,
      "position3d": [4, 6, 3], "aim3d": [0, 0, 0] }
```

```json
    { "id": "lampara", "type": "light", "light": "point", "color": "#8fb4ff", "intensity": 1.2, "radius": 600,
      "position3d": [-3, 2, 2] }
```

Una escena sin luces, sin luz de alrededor, sin cielo y sin `env` ilumina sus modelos con una luz
suave desde arriba a la izquierda de la cámara, para que un modelo nunca salga negro. La luz de
alrededor y el cielo (`canvas.ambient`, `canvas.sky`) llegan desde abajo y desde arriba de la
cámara. Como mucho 12 luces cuentan (8 en `t0` y `t1`).

## Sombras

Una luz puntual, un foco o una direccional con `"shadows": true` proyecta sombras de los modelos
sobre los modelos cuyos materiales las reciben. Una escena puede tener hasta 2 luces con sombras.

Los mapas de sombras miden 2048 píxeles de lado para una direccional, 1024 para un foco y un cubo
de seis caras de 512 para una puntual, hasta 4096 (1024 en teléfonos, 2048 en `t2`) y la mitad en
el nivel más bajo; `shadow_resolution` fija otro tamaño. `shadow_bias` evita las rayas (súbelo)
o las sombras separadas de su objeto (bájalo). Los equipos de escritorio (`t3`) dibujan las
sombras de las dos primeras luces que las proyectan, `t2` de la primera y `t0` y `t1` de ninguna.

Un mapa se vuelve a dibujar solo cuando cambia su luz, un objeto, una pose o un material que se
mece. Lo que se dibuja con `blend` o `add` y los materiales con `cast_shadows: false` no
proyectan; las piezas recortadas (`mask`) proyectan solo donde se dibujan. El pelo proyecta la
sombra de su largo en `q2` y `q3`. Es una aproximación: dibuja una sola cáscara, a 0,6 del largo, cortada a la densidad con el mismo patrón, y no todas las capas de pelo; en `q0` y `q1` solo proyecta la piel.

Desde la terminal: `wprs-ctl scene shadows MI-CARPETA sol --on true`.

## La cámara 3D

`camera3d` en la raíz de la escena es la cámara de los modelos, los grupos 3D y las capas
inclinadas:

```json
  "camera3d": {
    "fov": 40, "eye": [5, 3.5, 9], "center": [0, 0.5, 0],
    "paths": [{ "id": "vuelta", "loop": true, "ease": "in_out_sine",
      "keys": [{ "t": 0, "eye": [5, 3.5, 9], "center": [0, 0.5, 0] },
               { "t": 8, "eye": [-5, 3.5, 9], "center": [0, 0.5, 0] }] }]
  }
```

| Campo | Por defecto | Rango | Qué hace |
|-------|-------------|-------|----------|
| `fov` | 60 | 1 a 179 grados | El campo de visión. Puede seguir valores. |
| `near`, `far` | 0,1 y 1000 | | Los planos cercano y lejano. |
| `eye` | `[0, 0, 5]` | | Dónde está la cámara. Puede seguir valores. |
| `center` | `[0, 0, 0]` | | A dónde mira. Puede seguir valores. |
| `up` | `[0, 1, 0]` | | Hacia dónde está arriba. |
| `paths` | | hasta 16 | Recorridos que la cámara sigue. |
| `order` | `sequential` | `sequential`, `random` | Cómo se encadenan los recorridos. |
| `fade` | | | Cómo se unen: `{ "to": "black" o "cross", "duration": 0 a 10 s }`. |

### Recorridos

Cada recorrido es `{ "id", "keys", "ease", "loop" }`, con de 2 a 256 claves
`{ "t", "eye", "center", "up", "fov" }` en tiempo creciente (cada clave debe llevar `eye` y
`center`; `up` y `fov` son opcionales y, sin ellos, mantienen los de la cámara). La cámara pasa
por cada clave en una curva suave (Catmull-Rom). Un recorrido abierto mantiene su primera clave
hasta su primer `t` y dura hasta su última clave; con `loop` se cierra de vuelta a la primera, sin
saltos. `ease` da forma al tiempo de una vuelta.

Un recorrido abierto suena una vez y se queda en la última clave, sin pedir más fotogramas; uno
con `loop` da vueltas para siempre. Varios recorridos van uno tras otro (`sequential`) o en
orden nuevo cada ronda (`random`). `fade` los une: `black` oscurece la segunda mitad de la
duración de un recorrido y aclara la primera mitad del siguiente (toda la escena, las capas planas
incluidas); `cross` dibuja el final de un recorrido sobre el principio del siguiente, mezclando los
modelos. Los recorridos que se mueven piden fotogramas, hasta `max_fps` y como mucho 30 por
segundo en el nivel de calidad más bajo.

Los scripts leen y cambian `scene.camera3d` (`fov`, `eye`, `center`, `up`); lo que ponen gana sobre
los recorridos (ver [scripts.md](scripts.md)).

Desde la terminal: `wprs-ctl scene camera3d` fija la cámara y `wprs-ctl scene camera-path`
añade, pone claves, ordena y funde recorridos.

## Dar profundidad a capas planas

Hay cuatro formas de dar profundidad a una escena de imágenes planas.

### Inclinar y alejar capas (`tilt`, `z`, `perspective`)

`transform.tilt` inclina una capa en profundidad alrededor de su posición (de -89 a 89 grados cada
uno: un `x` positivo lleva el borde de abajo hacia quien mira, un `y` positivo el borde de la
izquierda), y `transform.z` la acerca (positivo) o aleja (negativo) de quien mira. Se ven con
`canvas.perspective`, la distancia de quien mira en píxeles (de 100 a 100000); sin ella, se usa la
distancia a la que la altura del lienzo llena el `fov` de `camera3d` (o 45 grados). Una capa a
la altura de quien mira o detrás de él no se dibuja.

Una capa así se dibuja como un cuadrilátero proyectado: sin costo extra. Sus efectos corren en su
propio plano antes de proyectarse y su máscara se inclina con ella. Un grupo inclinado se dibuja
aparte una vez más y se proyecta entero, y sus capas se inclinan con él. El puntero encuentra la
capa inclinada donde se ve.

```json
    { "id": "cartel", "type": "shape", "shape": { "rect": { "size": [640, 360], "radius": 30 } }, "fill": "#ffffffcc",
      "transform": { "position": [960, 540], "tilt": [0, 25], "z": 120 }, "parallax": [0.03, 0.03] }
```

### Paralaje con el puntero (`parallax`)

Con `canvas.parallax` y el campo `parallax` de las capas (ver [escena.md](escena.md) y
[capas.md](capas.md)), cada capa se mueve un poco distinto cuando el puntero se mueve, o cuando
se inclina el teléfono (`gyro`): las lejanas (0,01) menos que las cercanas (0,05).

### Un mapa de profundidad (`depth_parallax`)

El efecto `depth_parallax` mueve cada punto de una imagen según un mapa de profundidad
(un recurso `linear`: lo claro está cerca): al mover el puntero (`follow`) o en una órbita lenta
(`orbit`), lo cercano se desliza sobre lo lejano sin romperse. Con `smooth` sigue el puntero
como lo hace `canvas.parallax`, para que la profundidad y el paralaje de las capas se muevan
juntos. `steps` (de 8 a 24, 16 por defecto) son los pasos de la búsqueda: 24 cuesta la mitad más
en `q3` y está limitado a 12 en `q2` y 8 en `q1`. `overscan` agranda la capa para esconder los
bordes. Mientras no mueva nada, no cuesta ninguna pasada; en el teléfono, cuyo puntero solo sigue
al toque, casi siempre se ve así.

```json
    { "id": "fondo", "type": "image", "image": "cielo", "size": [1920, 1080],
      "effects": [{ "effect": "depth_parallax",
        "params": { "depth": "profundidad", "strength": 40, "focus": 0.5, "steps": 16, "follow": true, "orbit": true } }] }
```

Un mapa de profundidad se hace con una herramienta de profundidad o a mano (en el ejemplo, un
degradado de grises). En el editor hay un pincel de profundidad y el programa puede estimarla a
partir de una imagen con un modelo de profundidad que se descarga a petición
(`wprs-ctl models download depth-anything-v2-small --yes`; ver [cli.md](cli.md)).

### Capas de malla con profundidad

Una capa `mesh` puede usar la profundidad de sus vértices con la perspectiva de `canvas.perspective`
(ver [mallas.md](mallas.md)).

## HDR y mapa de tonos

Con `canvas.hdr: true` los colores más brillantes que el blanco se guardan en imágenes de 16 bits,
y los modelos se dibujan en 16 bits. `canvas.tonemap` (`none`, `aces` o `agx`, solo con `hdr`) los
aprieta hasta la pantalla en una última pasada. En una pantalla con salida HDR el último paso
conserva los 16 bits y dobla suavemente lo que pasa de 0,8 del blanco hacia el máximo de esa
pantalla, manteniendo el tono y los medios tonos. `canvas.bloom.hdr` fija el umbral y la fuerza
del resplandor en `q3`.

Desde la terminal: `wprs-ctl scene tonemap MI-CARPETA --hdr true --map aces`.
